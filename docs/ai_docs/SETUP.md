# Setup wizard

Settings → Run setup (opens automatically when no channels/agents exist). Steps: Welcome → Channels → Discover → Evaluator → Review → Done (`packages/webview/src/SetupWizard.tsx`).

- **Channels:** use existing channels or add a new one (presets: Ollama, OpenAI, OpenRouter, LM Studio, other OpenAI-compatible, Claude CLI). API keys go to the IDE secret store (`secret.set`); YAML holds only `secretRef`. Each channel is auto-tested; errors map to fixes. The step also picks the channel + agent used as the AI evaluator (falls back to channel models when a channel has no agents); all models on ok channels are discovered.
- **Discover (quick probe):** one server-owned, ordered smoke-test queue per project (`SetupProbeRunner` in `modules/setup/src/probe.ts`, protocol `setup.probe.start|status|cancel|retry`, progress via `setup.event` `{kind:"probe.state"}`). Every discovered channel:model gets one tiny chat request ("Reply with exactly: OK", no tools, `maxTokens` 32) under a hard 30 s deadline that starts at scheduler admission and covers the request through stream completion; queue wait is tracked separately as `waitMs`. One candidate at a time; duplicates skipped. Order: Ollama models first, then Claude CLI, then the rest ranked by the selected evaluator (`rankCandidates`, 20 s bound, deterministic fallback on failure/timeout). Verdicts: **green** (text reply), **orange** (timeout), **red** (HTTP/auth/malformed/empty/tool-only/missing completion), **skipped** (never reached, cancelled, or channel wedged). "Accept and continue" aborts the in-flight probe and marks the rest skipped; results persist for the wizard session so re-entering the step never re-probes. "Retry failed" re-queues non-green candidates explicitly, bounded at 3 attempts each, preserving `lastReason`/`attempts` diagnostics. Run ownership: each run has a `runId` and a fingerprint of enabled channels + candidates + evaluator — a changed fingerprint or re-attach cancels the old run and late results are discarded; results are in-memory only, so an IDE restart yields a fresh `idle` runner (never inherited greens). Adapters that ignore abort: the channel is drained up to 10 s (`PROBE_DRAIN_MS`); same-channel candidates are then skipped instead of overlapping the zombie request. Failure reasons are normalized (provider bodies stripped) and redacted against stored secrets before reaching the snapshot/UI/logs. Snapshots carry per-state `counts`. Full `benchModel()` stays opt-in behind "Measure speed" and runs inside `setup.recommend` (`bench: true`), separate from the quick pass.
- **Evaluator:** `rules` (default, no model call) or `ai` (chosen model refines; must itself be green unless `evaluatorAny` is passed).
- **Review:** editable role → `channel:model` table with reasons/warnings; only green candidates are offered; unfillable roles are disabled. Apply writes `agents.yaml` + `roles.yaml`. While `recommendBusy` a `BusyNote` (spinner + elapsed seconds, `Busy.tsx`) shows a mode-specific label (rules / AI refine / bench) and Apply is disabled with `aria-busy`.

In-progress work across the wizard shows `Spinner`/`BusyNote` and buttons latch (`disabled` + `aria-busy`): channel test/retest, Add channel, probe start/running/ranking, Retry failed (until the next `runId` reports running), Build proposal, Apply, Done-step saving/undo. The Done step shows "Saving configuration…" until `setupSaved`/`setupError` arrives; an error without `setupSaved` shows "Save failed".

## Engine (`modules/setup`: `assign.ts`, `recommend.ts`, `probe.ts`; core handlers in `packages/core/src/handlers/setup.ts`)
`scoreAssignments` filters on hard requirements (tools, vision, imageGen), ranks by soft weights (size parsed from name, reasoning, coder name, native tools, context, local/free), spreads near-equal load across models. AI picks failing hard requirements are dropped. `recommendAssignments` accepts `eligible` (green smoke pairs, in probe order — filters discovered models and orders candidates) and `evaluatorAny`. With zero green candidates it fails with "no models passed the smoke test" (recoverable via retry/back). Protocol: `setup.recommend {mode?, evaluator?, evaluatorAny?}`, `setup.probe.*`.

## Cost flag
Agents carry optional `costs: boolean`. Default is derived: `priced`/`reported` billing, or a `claude-cli` channel. Settings shows a `$ costs` badge on the agent and on every role whose agent costs. The wizard sets `costs: true` on Claude CLI agents.
